# Temporary game availability (local implementation)

`COUP_TEMPORARILY_DISABLED` is validated at API startup. Omitted or `true` pauses new Coup admission; only the literal `false` removes the pause. Invalid values fail startup. This is configuration only: no game records, engine versions, assets, historical results, sessions, admission files, infrastructure timers or worker policies are changed.

The authenticated, rate-limited, no-store new `GET /v1/games/availability` endpoint returns versioned `lobbyAvailability` metadata. Existing catalog responses remain unchanged. Coup is `TEMPORARILY_DISABLED` while paused. When unpaused it is `AVAILABLE` only for users already allowed by the personal profile, owner admission and transport configuration. All other home games, including Kahroba, remain `COMING_SOON`; no rollout approval or admission is granted. The legacy public catalog remains non-playable. Room creation/join/start and public matchmaking continue to enforce their existing catalog checks.

Personal match creation checks `newMatchesAllowed` inside the existing serialized admission transaction, after authorized idempotent recovery and before any writes. The default is deny. New starts return the existing stable `GAME_UNAVAILABLE` code. Existing command IDs may return their previously committed match, including finished/terminated views. `current`, authorized read/subscribe/catchup, commands and close remain available with both retained engine pins.

The lobby consumes verified metadata and fails closed when missing, invalid or unavailable. Inactive artwork uses CSS grayscale, saturation/brightness and a charcoal overlay; text and card opacity remain intact. Tiles are native disabled buttons with Persian labels and a decorative lock, without start arrows. Existing-match recovery has a separate link; direct match IDs support historical authorized views. Availability refetches use normal query lifecycle; no infrastructure timer renewal is introduced.

To safely re-enable in a separately approved release: explicitly set `COUP_TEMPORARILY_DISABLED=false`, retain all existing owner/transport/auth admission configuration, run local verification, and obtain deployment approval. Do not activate Kahroba, change public game status or expand admission. Removing the variable restores the pause. Applying configuration to a running environment is outside this local task; no services were restarted.

Local checks use config/API/web unit tests, isolated PostgreSQL personal-match tests, and `pnpm --filter @hambazi/web test:midnight` with the locally built bundle and fully intercepted synthetic transport. The fixture's staging-shaped URLs resolve through Playwright interception to loopback servers; they never contact live staging. Screenshots are captured at 320, 375 and 390 pixels in both Chromium and WebKit.
