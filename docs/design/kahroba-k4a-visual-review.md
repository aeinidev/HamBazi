## Capture inventory

For **each of Chromium and WebKit**: five affordable tables (320×568, 360×740, 375×667, 390×844, 768×1024), three payment sheets (320/375/390), return sheet, noble choice, sole victory, shared victory and enlarged-text 320 = thirteen per browser.

No blocking layout defect was identified in these retained captures with the K3 interactive checks. This is not exact visual parity, native Telegram acceptance or owner aesthetic sign-off. The quiet ornament, taller narrow cards, small gems and scrolling are explicit differences; no redesign was performed in K4A. Native bottom inset, fullscreen/back behavior and the keyboard need the approved two-account K4B test.
