# توقف استقرار Profile Hub روی Staging

این گزارش مربوط به تلاش اول است. رفع خطای Web، بکاپ و نتیجهٔ تلاش بعدی در [گزارش استقرار دوم](profile-hub-staging-r2-20261110.md) ثبت شده است.

نتیجه: استقرار در کنترل اجرای Image نهایی و پیش از Maintenance متوقف شد؛ نسخهٔ جدید روی Staging فعال نشده است. Production تغییری نکرد.

## خطای مسدودکننده

Image جدید Web با شناسهٔ `sha256:405c42b0ecddc33b5a26d8264d6c2c20aa2bc735b8c160b5bbece0249422587e` در محیط جداشده، بدون شبکه و با تنظیمات production، با کد خروج ۱ و پیام `WEB_STATIC_STARTUP_FAILED` متوقف شد.

دو فایل عمومی `vendor/heic-to/LICENSE.txt` و `vendor/heic-to/NOTICE.txt` پسوندی دارند که سرور استاتیک فعلی نمی‌پذیرد. سرور در مرحلهٔ جمع‌آوری فایل‌ها چنین دارایی‌هایی را رد می‌کند. تست‌های مرورگر که از Vite Preview استفاده می‌کنند این ناسازگاری را آشکار نکردند؛ کنترل اجرای Image نهایی آن را یافت. فایل‌های مجوز باید حفظ شوند و پشتیبانی امن از فرمت آن‌ها پیش از تلاش بعدی بررسی شود.

## بررسی‌های انجام‌شده

- lint، مرزهای معماری، typecheck و قراردادهای API روی بستهٔ جداشده از نسخهٔ مبنای Staging گذشتند.
- ۱۰۸۶ تست API، ۱۴۵ تست واحد Web و ۲۵ تست یکپارچهٔ HTTP/PostgreSQL/Redis گذشتند.
- ۴۲ تست مرورگر پروفایل/چیدمان در Chromium و WebKit و ۸ تست امنیت مرورگر/CSP گذشتند.
- ۲۰۷ تست زیرساخت گذشتند؛ ۳ تست وابسته به محیط اسکنر اجرا نشدند.
- اسکن اسرار دارایی‌های عمومی: صفر یافته. audit وابستگی‌های production: یک مورد moderate، صفر high/critical.
- اسکن تازهٔ ابزار Migration با پایگاه آسیب‌پذیری سرور: یک مورد medium و بدون یافتهٔ مسدودکننده. کنترل کامل Imageهای کاندید تکمیل نشد.

## وضعیت پس از توقف

کنترل نهایی روی Staging هویت همان ۷ کانتینر قبلی، سلامت سرویس‌ها و اعتبار کنترل‌های امنیتی Core/Admin را تأیید کرد. صفحهٔ عمومی و Admin پاسخ ۲۰۰ با TLS معتبر داشتند؛ پروفایل بدون احراز هویت ۴۰۱ و مسیر سلامت خصوصی از اینترنت ۴۰۴ بود.

دیتابیس همچنان ۲ کاربر، ۲۱ Migration و صفر Migration ناموفق دارد؛ ستون‌های جدید پروفایل ایجاد نشده‌اند. فایل‌های پذیرش کاربران با binding امنیتی فعلی برابرند. محدودیت کاربران فعلی حفظ شده است. Image کاندید API فقط بارگذاری شد و اجرا نشد؛ فایل‌های آماده‌سازی و شواهد در پوشهٔ خصوصی انتشار باقی مانده‌اند.

به‌دلیل خطای مسدودکننده، Maintenance، ساخت بکاپ تازه، آزمون بازیابی همان بکاپ، Migration و جایگزینی سرویس‌ها آغاز نشدند. آزمون احرازشدهٔ نسخهٔ جدید روی Staging و آزمون Telegram روی دستگاه واقعی نیز اجرا نشدند. تلاش بعدی به رفع خطای شروع Web، کنترل دوبارهٔ Imageها و یک بکاپ تازه با بازیابی موفق نیاز دارد؛ بکاپ‌های قبلی جایگزین این شرط نیستند.
