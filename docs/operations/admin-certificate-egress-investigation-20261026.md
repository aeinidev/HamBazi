# بررسی فقط‌خواندنی ارتباط ACME — ۲۶ اکتبر ۲۰۲۶

> **نتیجهٔ بعدی با تأیید جدا:** [Dry Run گواهی Admin](admin-certificate-dry-run-20261026.md) موفق شد. متن پایین سابقهٔ بررسی پیش از آن آزمون است؛ انتشار عمومی همچنان انجام نشده است.

## نتیجه

در بررسی مستقیم سرور از 08:12 تا حدود 08:18 UTC، مشکل قبلی تکرار نشد. درخواست مستقیم به directory اصلی و آزمایشی Let’s Encrypt، بدون Proxy یا تونل رایانهٔ اپراتور، HTTP 200 و TLS معتبر گرفت. **تمدید کامل هنوز آزمایش نشده و تأییدشده نیست.** هیچ Certbot renew/dry-run، تغییر تنظیمات، reload، نصب، Firewall یا تغییر گواهی اجرا نشد. Admin عمومی همچنان TLS handshake را رد می‌کند؛ فاز دو آغاز نشد.

**حد تشخیص:** رخداد قبلی انتظار بیش‌ازحد برای پاسخ upstream بوده است. ناپایداری موقت مسیر یا سرویس مقابل محتمل است، اما شواهد برای تعیین قطعی عامل در پارس‌پک، مسیر بین‌راه یا لبهٔ Let’s Encrypt کافی نیست. خطای تاریخی نباید صرفاً به IPv6، DNS، فیلتر دائمی یا Firewall نسبت داده شود. این نمونه‌برداری کوتاه، پایداری بلندمدت را ثابت نمی‌کند.

## اقدام پیشنهادی، فقط پس از تأیید جدا

ساده‌ترین مسیر، حفظ Certbot و timer موجود و خروجی مستقیم سرور است؛ فعلاً افزودن Proxy، VPN، سرویس خارجی، IP ثابت ACME یا تغییر سراسری IPv6 توجیه ندارد. طبق [راهنمای رسمی Let’s Encrypt](https://letsencrypt.org/docs/integration-guide/)، خروجی TCP/443 و برای HTTP-01 ورودی TCP/80 لازم است و IPهای سرویس ثابت نیستند.

مرحلهٔ بعد، پس از تأیید مالک، آزمون محدود `certbot renew --cert-name hambazi-admin --dry-run --run-deploy-hooks --no-random-sleep-on-renew` با بازبینی hookهای مؤثر و شواهد قبل/بعد است؛ این فرمان **اجرا نشده است**. dry-run عملیات صرفاً خواندنی نیست و می‌تواند فایل آزمایشی/حساب staging و reload ایجاد کند. [مستندات Certbot](https://eff-certbot.readthedocs.io/en/stable/using.html) اجرای deploy hook در dry-run را نیازمند flag صریح می‌داند؛ موفقیت challenge و reload باید جدا تأیید شوند.

آزمون باید فقط همین lineage را هدف بگیرد، certificate فعال سایر سایت‌ها را تغییر ندهد، Nginx را restart نکند و وضعیت Bot/API/سایت بازیکنان را قبل و بعد بررسی کند؛ reload روی Nginx مشترک اثر عملیاتی بالقوه دارد و تضمین مطلق بی‌اثری داده نمی‌شود. public Admin برای HTTP-01 لازم نیست و بسته می‌ماند. اگر timeout دوباره رخ داد، ثبت زمان/مقصد/مرحلهٔ اتصال و پیگیری مسیر با پشتیبانی پارس‌پک مقدم بر افزودن سرویس جایگزین است؛ تیکتی ارسال نشده است.
