# چک‌لیست QA زندهٔ فاز چهارم Admin

وضعیت همهٔ موارد زیر **اجرانشده در Staging** است. این سند و تست محلی مجوز QA یا استقرار نیستند. اجرای آینده به مجوز همان انتشار، شواهد امنیتی معتبر، بکاپ نهاییِ بازیابی‌شده و فرماندهٔ انتشار مشخص وابسته است. مرجع اجرا: [برنامهٔ انتشار](admin-phase-4-staging-release-plan.md).

## قواعد اجرا و ثبت شواهد

- ورود OWNER فقط توسط مالک، در مرورگر خصوصی و بدون ضبط انجام شود؛ Password، PIN، Cookie، token، verifier، کلید یا تصویر فرم برای عامل ارسال نشود. Password/PIN واقعی تغییر نکنند؛ PIN اشتباه، قفل عمدی، Bootstrap یا Recovery واقعی آزموده نشوند.
- آزمون‌های نوشتن فقط با مجوز صریح QA و روی نقش، مدیر، کاربر، بازی، اتاق و Match مصنوعیِ همان آزمون انجام شوند. کاربر واقعی، بازی رتبه‌بندی‌شده/مسابقهٔ فعال واقعی و حساب OWNER هدف mutation نباشند. اگر fixture امن موجود نیست، مورد مسدود گزارش شود، نه PASS.
- فقط شناسهٔ QA/نسخهٔ artifact، زمان، شناسهٔ هدف مصنوعی، status/errorCode، شناسهٔ receipt/Audit و نتیجه ثبت شود. Board، کارت، نقش مخفی، RNG، event payload، chat، private note و اطلاعات ورود وارد گزارش، screenshot، trace یا لاگ نشوند.
- پیش‌نمایش و تأیید به‌تنهایی اجرای عملیات نیستند؛ receipt اجرای همان commandId و Audit آن لازم‌اند. خطا/UNKNOWN با درخواست تازه دور زده نشود؛ وضعیت همان عملیات و reconciliation مصوب بررسی شود.

## رسید QA و تصمیم

برای هر ردیف وضعیت PASS/FAIL/BLOCKED/NOT_RUN، زمان، نسخه/ایمیج دقیق، نقش اجراکننده، هدف مصنوعی و شاهد امن ثبت شود. PASS کل فقط پس از تمام موارد اجباری و رفع مورد بازِ 403/ابطال نشست ممکن است. افت سرویس، افشای اطلاعات، تغییر غیرمجاز OWNER، ابهام اثر عملیات یا خطای داده فوراً containment و حفظ شواهد می‌خواهد؛ credential یا DB با حدس restore نشوند.

تست ظرفیت/Load/Stress/Soak به سرور آینده موکول است؛ این QA تأیید ظرفیت یا Production نیست و فاز پنجم را آغاز نمی‌کند.
