# Profile Hub؛ رفع Web و توقف ایمن استقرار دوم

این گزارش تاریخی است. مشکل بسته‌بندی در Image اصلاح و نسخهٔ جدید در تلاش بعدی [با موفقیت مستقر شد](profile-hub-staging-deployed-20261110.md).

نتیجه: خطای شروع Web رفع و Image نهایی تأیید شد؛ بکاپ تازه و بازیابی کامل موفق بودند. استقرار هنگام اجرای Prisma با `P3015` متوقف شد. هیچ Migration اعمال نشد و همان نسخهٔ قبلی Staging سالم به سرویس بازگشت. Production تغییری نکرد.

## اصلاح Web و تست‌ها

سرور استاتیک، فایل‌های عمومی با پسوند ناشناخته را پیش از بازکردن پورت رد می‌کرد. اضافه‌شدن `vendor/heic-to/LICENSE.txt` و `NOTICE.txt` به خروجی Web، به همین دلیل `WEB_STATIC_STARTUP_FAILED` ایجاد می‌کرد.

در `apps/web/server/serve.mjs` فقط MIME صریح `.txt` برابر `text/plain; charset=utf-8` اضافه شد. هر دو فایل مجوز با محتوای اصلی حفظ شدند؛ `nosniff` و سیاست `no-store` نیز برقرارند. تست رگرسیون با فایل‌های واقعی ابتدا همان خطا را بازتولید کرد و پس از اصلاح گذشت.

- ۲۲ تست بسته‌بندی و مجموعهٔ زیرساخت با ۲۰۸ تست موفق و ۳ مورد وابسته به محیطِ اجرا‌نشده گذشتند؛ formatting و lint فایل‌های اصلاح‌شده نیز گذشتند.
- Image نهایی Web هم محلی و هم روی سرور، در کانتینر جداشده بدون شبکه، readiness سالم داشت. CSP، Brotli، مسیرهای خصوصی و برابری بایت‌های هر دو مجوز تأیید شدند.
- Image تأییدشدهٔ سرور: `sha256:030d12df4f48cb6c0f6fcb7c9544ba51db7904408ffa0bd3ac2cde2cc8deea10`.
- اسکن تازهٔ شش سرویس، Imageهای بازگشت API/Web و ابزار Migration با سیاست فعلی امنیتی، یافتهٔ مسدودکننده نداشت. محدودیت زمانی شواهد امنیتی تمدید دلخواه نشد.
- نتایج قبلی همان بستهٔ جداشدهٔ پروفایل شامل ۱۰۸۶ تست API، ۱۴۵ تست Web، ۲۵ تست یکپارچه، ۴۲ تست مرورگر پروفایل/چیدمان و ۸ تست CSP موفق است؛ این‌ها آزمون نسخهٔ جدید روی Staging فعال محسوب نمی‌شوند.

## بکاپ و بازیابی واقعی

پس از توقف نویسندگان Core و Admin، صفر Match فعال و صفر اتصال نویسندهٔ دیگر تأیید شد. PostgreSQL و Redis حفظ شدند؛ فقط timerهای تمدید و Certbot موقتاً متوقف شدند و timerهای مستقل انقضای امنیت فعال ماندند.

بکاپ تازه با شناسهٔ `profile-hub-20261110-r2-d73b3a1f` ساخته و همان فایل رمز‌شده به میزبان جدا منتقل شد:

- اندازه: `124320102` بایت.
- SHA-256: `f6c43c8f4e8a2b5008aced58d46611e1e0d1d001e7dd1bb4d82b1175a83ca6b8`.
- مسیر محلی: `/home/mehdi/.local/share/hambazi/backups/staging/profile-hub-20261110-r2-d73b3a1f/`.

بازیابی همان فایل در PostgreSQL جداشده، بدون شبکه، volume یا پورت میزبان انجام شد. تطبیق کامل هر دو دیتابیس، ۴۵ جدول، ساختار، نقش‌ها، دسترسی‌ها، تنظیمات و کلیدها، `pg_amcheck` و پاک‌سازی محیط آزمون موفق بودند. فایل `restore.json` رسید این بررسی است. آرشیو هفت Image فعلی نیز خارج از سرور ذخیره و تمام ۷۵ blob آن با SHA-256 و descriptorهای OCI تأیید شد. کلید خصوصی بکاپ روی میزبان محلی باقی ماند.

پیش از فرمان Migration، پذیرش نهایی بکاپ دوباره روی سرور، وضعیت واقعی داده‌ها و تنظیمات را تطبیق داد.

## علت توقف Migration و بازیابی سرویس

خطای `P3015` از بسته‌بندی آماده‌شده برای استقرار بود: پوشهٔ Migration جدید با مالکیت root و مجوز `700` و فایل SQL با مجوز `600` منتقل شده بود، در حالی که ابزار Migration با کاربر `1000:1000` اجرا می‌شود. آزمون خواندن همان مسیر با همان Image و کاربر، بدون شبکه و بدون اتصال دیتابیس، خطای `EACCES` را بازتولید کرد. هیچ مجوز یا فایل SQL روی سرور برای تلاش مجدد تغییر داده نشد و Migration تکرار نشد.

پیش از راه‌اندازی مجدد نسخهٔ قبلی، پذیرش کامل بکاپ، تطبیق هر ۴۵ جدول، ساختار، نقش‌ها و دسترسی‌ها، ۲۱ checksum دفتر Migration و نبود ستون‌های جدید ثابت کرد که هیچ تغییری اعمال نشده است. نشانگر شروع Migration و شواهد خطا حفظ شدند؛ داده‌ای از بکاپ روی سرور زنده بازنویسی نشد.

همان هفت کانتینر قبلی و تنظیمات اصلی بازگردانده شدند. بررسی نهایی، سلامت Core/Admin، پذیرش بدون تغییر دو کاربر، ۲۱ Migration موفق، صفر Migration ناموفق، صفر ستون جدید و فعال‌بودن همهٔ timerهای اصلی را تأیید کرد. پاسخ عمومی Web و Admin برابر ۲۰۰ با TLS معتبر، پروفایل بدون احراز هویت ۴۰۱ و مسیر سلامت خصوصی از اینترنت ۴۰۴ بود.

برای تلاش بعدی، دسترسی فقط دارایی‌های عمومی Migration باید پیش از مهرکردن ورودی‌ها اصلاح و خواندن همهٔ ورودی‌ها با کاربر واقعی ابزار، پیش از Maintenance آزمایش شود؛ فایل‌های حاوی credential باید خصوصی باقی بمانند. بکاپ و پذیرش سازگار با وضعیت تازه نیز لازم است.

نسخهٔ جدید پروفایل روی Staging فعال نشده است؛ آزمون احرازشدهٔ مرورگر روی آن و آزمون Telegram روی دستگاه واقعی اجرا نشدند. audit وابستگی‌های production یک هشدار moderate و صفر high/critical داشت.
